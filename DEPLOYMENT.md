# Deploying DocLens

DocLens has two deployable parts: the **FastAPI backend** (needs Postgres with
pgvector) and the **Next.js frontend**. The recommended split is the backend on
a container host (Render) and the frontend on Vercel.

Deploy the **backend first** — the frontend needs its URL at build time.

## 1. Backend + database on Render

1. Push this repository to GitHub.
2. On <https://render.com>, choose **New → Blueprint** and select the repo. Render
   reads [`render.yaml`](render.yaml), which provisions:
   - a free Postgres database (`doclens-db`), and
   - a Docker web service (`doclens-api`) built from `backend/Dockerfile`.
3. After the first deploy, open the `doclens-api` service → **Environment** and set:
   - `GEMINI_API_KEY` — your Gemini key
   - `CORS_ORIGINS` — your frontend URL (add it once you have it from step 2 below,
     e.g. `https://doclens.vercel.app`)
4. The app enables the `vector` extension and creates its tables on startup.
   Confirm health at `https://<your-api>.onrender.com/health`.

Notes:
- Render's `connectionString` comes as `postgresql://…`; the app rewrites it to
  the `postgresql+psycopg://…` driver form automatically.
- Render's managed Postgres supports `CREATE EXTENSION vector`.

## 2. Frontend on Vercel

1. On <https://vercel.com>, **Add New → Project** and import the repo.
2. Set **Root Directory** to `frontend`. Vercel auto-detects Next.js.
3. Add an environment variable:
   - `NEXT_PUBLIC_API_URL` = `https://<your-api>.onrender.com/api`
   (this is read at build time, so set it before the first build).
4. Deploy. Then copy the resulting URL back into the backend's `CORS_ORIGINS`
   and redeploy the backend so the browser is allowed to call the API.

## Environment variables reference

**Backend**

| Variable | Example | Notes |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://…` | Provided by Render; driver is normalised automatically |
| `JWT_SECRET` | long random string | Generated by Render blueprint |
| `GEMINI_API_KEY` | `AIza…` | Secret — set in dashboard |
| `CORS_ORIGINS` | `https://doclens.vercel.app` | Comma-separated; the frontend origin(s) |
| `CHAT_MODEL` | `gemini-2.5-flash` | |
| `EMBEDDING_MODEL` | `models/gemini-embedding-001` | |
| `EMBEDDING_DIMENSION` | `768` | Must match the vector column |

**Frontend**

| Variable | Example | Notes |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | `https://doclens-api.onrender.com/api` | Build-time; include the `/api` suffix |

## Alternatives

- **Railway / Fly.io** work the same way — point them at `backend/Dockerfile`
  and attach a Postgres with pgvector (Railway's `pgvector` template, or run the
  `pgvector/pgvector` image).
- The whole stack also runs locally with `docker compose up --build`.
